# ランニング用の自分専用ポッドキャスト（設計書）

状態：**設計のみ・未実装**（2026-10-14）。実装はユーザーの指示があってから。
疑問が出たら、この文書の「決めたこと」と「未決」を見て、未決はユーザーに確認する。

## 目的

- 週 3 回・30 分〜1 時間のランニング中に、音楽の代わりに英語を聞く
- 机で一度やった教材・復唱・単語を、耳で聞き直して復習する（走りながらでも分かる内容にする）
- iPhone の Podcast アプリで聞く。事前ダウンロード・ロック中の再生・速度変更・10 秒戻しはアプリの機能に任せる
- 毎日 PC から時計（Garmin）に MP3 をコピーする運用はしない

## 決めたこと（結論）

**Mac でエピソードの MP3 と RSS フィードを作り、Cloudflare R2 に置く。iPhone の Podcast アプリで、フィードの URL をフォローする。**

```
Mac（trainer podcast build / publish）
  │ 練習ログ・教材・ドリルの音声を ffmpeg でつなぐ
  ▼
Cloudflare R2（公開バケット・独自ドメイン）
  https://<hostname>/<secret>/feed.xml        … RSS フィード（直近 10 本）
  https://<hostname>/<secret>/YYYYMMDD-HHMM.mp3 … エピソード
  ▲ hostname と secret は公開リポジトリに書かない（.env）
  │
iPhone の Podcast アプリ（「URL で番組をフォロー」）
```

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 置き場所 | Cloudflare R2 | Podcast アプリはいつ取りに来るか分からない。trainer＋tunnel だと、tunnel を起動している間しか取れない（tunnel は指示があるときだけ起動する決まり）。R2 なら trainer・tunnel と切り離せ、trainer 本体は Access で守られたまま |
| 認証 | かけない。URL に推測できない secret を入れる | Podcast アプリは Cloudflare Access のログインを通れない。中身は自分の英語の練習音声だけで、知られて困る情報は入らない |
| 費用 | 0 円 | R2 の無料枠は 10 GB・転送料なし。1 本 30 分（モノラル 64 kbps で約 14 MB）を 10 本残しても十分に収まる |
| 作るタイミング | ユーザーが「ポッドキャストを作って」と言ったとき。自動では作らない | ユーザーの判断（2026-10-14） |
| 更新の声かけ | Claude が「そろそろ更新しませんか」と提案する（下の「運用」） | ユーザーの希望（2026-10-14） |
| 記録 | 残さない。聞いた時間も journal に数えない | ユーザーの判断（2026-10-14） |
| 日本語の音声 | 入れない | ユーザーの判断（2026-10-14）。英語だけで、ElevenLabs の追加のクレジットもかけない |

## エピソードの中身

1 本約 30 分。1 時間走る日は 2 本聞く。前のエピソードを作ってから今までにやった練習から、材料を自動で選ぶ。

| 順番 | 中身 | 並べ方 | 材料の出どころ |
|---|---|---|---|
| 1 | 教材 | AI 教材の音声をそのまま（1 本約 1 分半） | 前回のエピソード以降にやった教材（`practice/lesson/`）。2 本に満たなければ、それより前の教材で補う。最大 3 本 |
| 2 | 復唱 | 英文 → 無音（英文の長さ × 1.5、最低 2 秒）→ 同じ英文 | 前回以降に × を付けた復唱（`practice/versant/`）と、最後にやった範囲。無音の間にマンブリングで真似する |
| 3 | 単語 | 英単語 → 無音 1.5 秒 → 同じ英単語 | 前回以降に × を付けた単語と、やったテーマの単語（`practice/vocab/`） |

- 1〜3 を 1 周して 30 分に満たなければ、2 と 3 をもう 1 周する。それでも足りなければ、そこで終える（無理に水増ししない）
- 各パートの頭に、短い効果音か 2 秒の無音を入れて区切る（日本語の案内は入れない）
- 声ごとに音量が違うので、ffmpeg の loudnorm で音量をそろえる
- 即答は入れない。質問の音声しか無く、答えの音声が無いため（「あとで検討」）
- 単語の例文は入れない。例文の音声が無く、作るとクレジットを使うため（「未決」）

## 運用（実装したら CLAUDE.md に書く）

- ユーザーが「ポッドキャストを作って」と言ったら、`trainer podcast build` → 中身を確かめる → `trainer podcast publish` の順に実行し、エピソードの中身（教材の題名・復唱と単語の数）を伝える
- **更新の声かけ**：開始の合図（Hello）を受けたとき、次のどちらかに当てはまれば、今日の流れの最後に「そろそろポッドキャストを更新しませんか」と一言添える
  - 前のエピソードから 7 日以上たった
  - 前のエピソード以降に、教材 3 本以上、または × を付けた復唱・単語が合わせて 30 以上たまった
- 声かけは提案だけで、ユーザーが頼むまで作らない

## 実装手順

### 1. エピソードを作る — `src/trainer/podcast.py`（新規）、`cli.py`

- `uv run trainer podcast build [--minutes 30] [--since YYYY-MM-DD]`
  - `--since` を省くと、前のエピソードの日時以降の練習を使う（前のエピソードは `podcast/episodes.json` で分かる）
  - 材料を選び、ffmpeg で 1 本の MP3（モノラル・64 kbps）にする。無音は ffmpeg の `anullsrc` で作る
  - 中身（教材の題名・復唱の ID と英文・単語）を `podcast/episodes.json` に足す。フィードの説明文に使う（アプリで何が入っているか読めるように）
- 作った MP3 は `podcast/`（リポジトリ直下・git 管理外）に置く。`episodes.json` は git 管理する（どの回に何を入れたかを残すため）

### 2. R2 に置く — `trainer podcast publish`

- `podcast/episodes.json` の直近 10 本から RSS フィード（RSS 2.0 ＋ iTunes のタグ）を作り、MP3 とフィードを R2 にアップロードする。10 本より古い MP3 は R2 から消す
- アップロードは R2 の S3 互換 API を boto3 で使う（wrangler の対話ログインが不要で、コマンド 1 つで終わるため）
- `.env` に足す項目（`.env.example` にも項目名だけ書く）
  - `R2_ACCOUNT_ID`・`R2_ACCESS_KEY_ID`・`R2_SECRET_ACCESS_KEY`・`R2_BUCKET`
  - `PODCAST_BASE_URL`（`https://<hostname>/<secret>`。secret は 32 文字程度のランダムな文字列）

### 3. Cloudflare の設定（ユーザーと一緒に、Chrome で）

1. R2 を有効にし、バケットを作る
2. バケットに独自ドメイン（例：`podcast.<既存のドメイン>`）をつなぐ。r2.dev のサブドメインは速度制限があり、本番向けではないので使わない
3. R2 の API トークン（そのバケットの読み書きだけ）を作り、ユーザーが `.env` に書く（チャットに貼らない）

### 4. iPhone で登録（ユーザー）

- Podcast アプリの「ライブラリ」→「URL で番組をフォロー」に `PODCAST_BASE_URL/feed.xml` を貼る
- 自動ダウンロードをオンにする

### 5. テスト — `tests/test_podcast.py`（新規）

- 材料の選び方（前回以降の教材・× の付いた復唱と単語・不足時の補い方）
- フィードの XML（直近 10 本・enclosure の URL と長さ・日付の書式）
- ffmpeg と R2 は呼ばずに、組み立てる命令とファイル一覧を確かめる

### 6. README・CLAUDE.md への追記

- README：ポッドキャストの作り方と、Cloudflare・iPhone の設定手順
- CLAUDE.md：上の「運用」
